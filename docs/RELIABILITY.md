# RELIABILITY.md

본 문서는 `semicap-valuation`의 신뢰성(데이터 수집·가용성·복구) 기준의 SSOT다.

## 1. 데이터 수집 (Ingest) 파이프라인
- 트리거: Vercel Cron → `/api/cron/ingest` (매 거래일 1회, 장 마감 후).
- 단계: 외부 시세 소스 호출 → 정규화 → `daily_quotes` upsert → `valuation_scores` 재계산.
- 멱등성: `(company_id, trade_date)` 유니크 제약으로 **upsert**, 같은 날 재실행해도 중복 없음.

## 2. 외부 의존성 장애 대응
- 외부 시세 API 실패 시: 재시도(지수 백오프, 최대 3회) 후 실패하면 해당 종목은 **스킵**하고 나머지는 계속 진행한다(부분 실패 허용).
- 전일 데이터가 있으면 대시보드는 **마지막 성공 스냅샷**을 표시하고, 데이터 신선도(`as_of` 날짜)를 사용자에게 노출한다.
- 수집 결과(성공/실패/스킵 종목 수)를 로그로 남긴다.

## 3. 데이터 품질 가드
- PER 계산 시 EPS ≤ 0 또는 결측이면 PER를 `null`로 두고 점수 계산에서 제외한다.
- 비정상 값(예: 음수 주가, 극단치)은 적재 전에 거른다.
- 업종 평균/중앙값은 유효 PER을 가진 종목만으로 계산한다.

## 4. 가용성
- 읽기 경로(대시보드/상세)는 Supabase Postgres 읽기에만 의존하며, 외부 API 장애와 분리된다.
- 가능한 페이지는 서버 렌더 + 캐시(재검증 주기 ≥ 1시간)로 제공한다.

## 5. 관측성 (Observability)
- ingest 잡: 시작/종료/소요시간/처리 건수/실패 건수 로깅.
- 에러는 서버 로그(및 추후 Sentry 등)로 수집.
- 헬스 지표: 마지막 성공 수집 시각, 당일 적재된 종목 수.

## 6. 복구
- 특정 날짜 수집 실패 시 동일 엔드포인트 재실행으로 멱등 복구 가능.
- 점수만 잘못된 경우 `valuation_scores`만 재계산하는 경로를 둔다.

## 7. 백업
- Supabase 자동 백업 정책에 의존하며, 스키마는 `supabase/schema.sql`로 버전 관리한다.

## 8. SLO (초기 목표)
- 일별 수집 성공률 ≥ 99%
- 대시보드 가용성 ≥ 99.9%
- 데이터 신선도: 거래일 마감 후 다음 영업 시작 전까지 갱신
